## 一、项目概述

### 1.1 背景与问题

旅行规划是典型的高信息量任务：查景点、看天气、算预算、排行程、记偏好，全靠人手动跨多个网站完成，耗时且容易遗漏。目标就是做一个「一次对话就帮你排好行程」的工具。

### 1.2 项目目标

构建一个**对话式智能旅行规划系统**：用户说出「想去哪、玩几天、预算多少、什么偏好」（还可上传照片），系统自动完成——解析需求 → 检索本地攻略/拉取高德真实 POI → 生成每日行程 → 校准预算 → 补全坐标与天气，最终输出一份可直接使用的行程单，并可导出 Markdown / PDF。

### 1.3 价值点

- 串起完整工程链路：LLM 接入、Prompt 与结构化输出、RAG 检索与精排、缓存、外部 API 集成、前端联调、容器化部署
- 可运行可演示：真实调用 deepseek + 高德 + Chroma，效果直观
- 对初学者友好：分层清晰，每层都能单独测试

## 二、技术选型（按实际实现校准）

| 部分 | 选型 | 说明 |
|---|---|---|
| LLM | **deepseek-flash**（OpenAI 兼容） | 行程生成、单日编辑、Query Rewrite；原生支持图像理解 |
| 后端 | **FastAPI + Pydantic v2** | 接口层与数据校验 |
| 向量库 | **Chroma**（`langchain-chroma`） | 攻略切块入库与检索 |
| 嵌入 | **dashscope text-embedding-v3**（OpenAI 兼容） | 自建 `HttpEmbeddings`（httpx 直连，见 `rag/embeddings.py`） |
| 精排 | **dashscope qwen3-rerank**（可选） | cross-encoder 精排；未配置或失败时降级为 LLM 打分 → 规则打分 |
| 地图/天气 | **高德 Web 服务** | POI 搜索、地理编码、行政区划、路线（备用）、天气 |
| 缓存 | **Redis** | 天气/POI/检索结果缓存；不可用时优雅降级 |
| 存储 | **SQLite + SQLAlchemy** | 用户保存的行程（长期业务数据） |
| 前端 | **Vue3 + Vite + vue-router + Axios** | 三页面 + 高德地图组件 |
| 部署 | **Docker Compose**（nginx 托管前端并反代 `/api`） | 本地开发亦可用 start.ps1 / start.sh |

> 早期版本曾计划使用 hello_agents 框架、Tavily 搜索与命令行交互，**均未采用**；实际为 LangChain `ChatOpenAI` + 高德 + FastAPI/Vue3 Web 应用。检索精排也只实现到「配置驱动的可选精排」，不是必选的 cross-encoder 链路。

## 三、功能设计

### 3.1 核心功能（已实现）

1. **需求收集**：目的地、天数、预算、同行人、偏好（前端表单，含图片上传）
2. **实时信息查询**：高德 POI / 天气 / 行政区划
3. **行程生成**：按天分上午/下午/晚上三时段，每天含景点、餐饮、住宿与提示
4. **预算估算**：交通/住宿/餐饮/门票/其他 五项拆分，并做确定性校准
5. **偏好记忆**：由用户在前端保存行程，历史可查、可删
6. **行程单输出**：Markdown 与中文 PDF（含封面、分天章节、预算表、建议）
7. **图片识别（多模态）**：上传照片 → deepseek-flash 视觉理解 → 纳入规划
8. **自然语言编辑**：一句话修改某天行程，改动会回写存储
9. **Token 观测**：按 改写/精排/生成/编辑 四阶段统计，随行程持久化

### 3.2 未做（边界）

- 不做真实导航与订票（只做信息与规划）
- 不做多用户账号体系（单机单用户）
- **不计算相邻景点车程**（见 `map_service.enrich_itinerary` 注释：出发起点不确定，车程无参考价值，且可省一半高德请求）
- 不做 SQLite → Postgres 迁移

**双存储分工**

- **SQLite（长期业务数据）**：`TripRecord` 表存用户保存的行程；`storage_service` 提供增删查改与分页计数
- **Redis（短期高频缓存）**：统一 `trip_planner` 前缀 + JSON + TTL，被 weather / map / retriever / rag_tool 复用；**不可用时优雅降级**（直连上游，只变慢不崩）

**双模式生成**

- **A 级（有攻略的沉淀城市）**：RAG 增强生成
- **B 级（无攻略的动态城市）**：高德 POI 候选池 + POI ID 白名单约束（防幻觉）
- **C 级（资料不足）**：LLM 通用知识兜底并如实标注
- **D 级（省级输入）**：拒绝，提示选择具体城市

## 七、核心实现要点

### 7.1 结构化输出（不是 ReAct）

本项目**没有采用 ReAct 循环**。做法是：提示词要求「只输出合法 JSON」+ `response_format=json_object` + Pydantic `Itinerary` 校验三重约束，解析失败自动重试一次。原因：行程是固定结构的产物，让模型自由发挥 `Thought/Action` 反而更难约束。

### 7.2 防幻觉

- **B 级城市**：LLM 只能从高德候选池里选 POI，输出后由 `_validate_pool` 校验；池外地点用未使用的候选替换，无可替换则移除
- **A 级城市**：检索为空时不让模型自由发挥，改从攻略 `###` 标题提取真实地名作为候选
- **信息标注**：导出与响应都注明来源；预算标注为估算

### 7.3 检索链路

Query Rewrite（LLM 优先，规则兜底）→ Chroma 向量召回 top_k×2 → **三级精排** → 结果缓存。
精排三级：配置 `RERANK_MODEL` 时用 dashscope 专用 cross-encoder；失败退 LLM 打分；再失败退规则打分（关键词命中 + 城市匹配）。任一级失败都不影响出结果。

### 7.4 跨城过滤用 adcode

动态城市候选池原先靠城市名字符串包含判断归属，会把「大理白族自治州」其他县、或「西安」搜出的咸阳 POI 误判为同城。现优先按行政区划编码判定：普通地级市比前 4 位，直辖市比前 2 位；POI 无编码时回退字符串判定。

### 7.5 预算校准

LLM 给出的五项预算之和常与用户填写的总预算对不上。`normalize_budget` 做确定性校准：偏差 ±5% 内不动，超出则按比例缩放，并把四舍五入的零头补到最大项，保证五项之和精确等于总预算。

### 7.6 多模态

用户上传图片转 base64 → 以 data URI 放入 `HumanMessage.content` 与文本一同发送 → deepseek-flash 识别景点/场景/风格 → 结果注入规划上下文。

### 7.7 异常与容错

- 业务失败抛 `PlanningError` 子类，由全局 handler 统一映射 HTTP 状态，路由不重复写 try/except
- 所有 LLM 输出走 `json.loads` + Pydantic 校验，失败重试一次
- Redis 不可用、高德失败、精排失败均有降级路径

## 八、质量保障

### 8.1 测试

- **`backend/tests/`：pytest 离线套件（187 例，约 3 秒）**，不依赖网络/LLM/Redis——用 `monkeypatch` 顶替外部依赖、临时 SQLite 顶替真实库、内存假 Redis 顶替缓存
- **`backend/eval/`：RAG 检索评估（48 条用例）**，指标含 Top1/Top3 命中率、MRR、Noise Rate、跨城市污染，口径见 `eval/README.md`
- **`backend/scripts/test_m*.py`：里程碑端到端脚本**，直接运行，会调用真实外部服务

```bash
.venv/Scripts/python.exe -X utf8 -m pytest backend -q                    # 离线测试
.venv/Scripts/python.exe -X utf8 backend/scripts/evaluate_rag_retrieval.py # RAG 评估
```

### 8.2 三个验收用例

1. **基础**：`西安3天，预算2000，带小孩` → 输出 3 天行程 + 分项预算 + 来源
2. **记忆**：保存一次行程后，历史页可查看、可删除、可再次打开
3. **容错**：输入「四川省」→ 返回 400 并提示选择具体城市；不完整输入（只说「成都」）→ 用默认值生成并列出假设

## 九、风险与备选

| 风险 | 影响 | 备选 |
|---|---|---|
| 搜索 API 限额 / 网络抖动 | 实时信息查不到 | 降级用模型知识，标注「建议核实」 |
| LLM 输出格式不稳定 | 解析失败 | 强制 JSON + 校验 + 重试一次，仍失败抛 502 |
| 预算估算不准 | 用户质疑 | `normalize_budget` 显式校准并标注「估算」 |
| 高德 Key 泄露 | 配额被盗用 | Key 走环境变量、控制台配置域名白名单、定期轮换 |
| 行程内容幻觉 | 误导用户 | 候选池白名单 + 池外校验 + 来源标注 |
